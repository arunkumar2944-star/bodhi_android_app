# Offline work-session attendance

Open and start each workday online. Once the server has validated the active registered device, daily eligibility and office configuration, and the Android runtime has a trusted same-boot time anchor, the app caches a signed offline authorization and the company-scoped office policy. It lasts at most 12 hours from issue, capped at midnight IST. The original grant is retained during its validity so a later renewal does not invalidate a departure already observed under it.

An active work session may continue during connectivity or transient API failures. Fresh, accurate GPS and the office-specific Wi-Fi requirements still determine valid transitions. Unknown sensors never imply absence. If an access token expires while offline, it is used only as retained local session identity; no request is sent with it for offline events. A valid offline grant is independently required before any Room write.

AttendanceEventManager saves the original event UUID, trusted anchor/monotonic evidence and offline permit in Room as PENDING, then advances the local engine through the existing StoredForRetry path. It does not attempt an upload while operating under offline authorization. Offline CHECK_IN uses current verified presence, not a delayed-arrival proof that would require an unuploaded candidate on the server. A network-only job syncs the original record after connectivity returns. Only server acknowledgment means SYNCED.

The API authenticates the live session and registered device as usual, verifies the permit signature, employee/company/device scope, anchored effective event interval, IST workday and seven-day upload retention window, and rechecks that workday's CRM eligibility. Server location/evidence/state checks remain in force. Leave, holiday, manager pause, invalid evidence or conflicting attendance requires explicit review; rejected rows remain visible in Offline Data. The phone cannot receive a new manager restriction while disconnected; all offline marks remain provisional until this validation.

Checkout and logout revoke the cached grant. A new login, device/company/user change, reboot, new workday, explicit server denial, missing trusted time or expired authorization cannot inherit offline permission. GPS collection is bounded by remaining authorization. The existing visible manual-start requirement remains: this feature does not restart the app, enable tracking after checkout, or provide first-time/new-workday cold startup without internet. If the process is terminated, reconnect and open the app to restore monitoring.

Settings > Offline Data shows authorization expiry, offline state, pending offline records and server rejection details. Settings > Permissions shows offline monitoring status. The ongoing notification identifies offline attendance.

Room upgrades automatically from version 11 to 12 by adding nullable offlinePermit to attendance_events; existing records are retained. No Neon/PostgreSQL migration is required. Deploy CRM_TEST_Backend/main with offline permit issuance/revalidation before testing the updated APK. Bootstrap/day-policy and office configuration must succeed online once before disconnecting.

Verify offline return/BREAK_END, valid offline arrival, duplicate observations, expired authorization, logout and reboot. Reconnect and confirm the same UUIDs become SYNCED.
